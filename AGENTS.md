# HME Seed Vault — project rules

This project is the offline seed vault (remixed from HME Wallet). The everyday wallet lives in its own project; never re-add wallet, price, swap, sign-in or server features here.

- No network code in the app: no fetch, server functions, API routes, analytics or error reporting. Why: the vault runs on a never-online phone and the APK ships without the INTERNET permission.
- `scripts/patch-android-manifest.mjs` must keep removing every network permission with `tools:node="remove"` and keep `allowBackup="false"`. Why: plugins can merge INTERNET back in, and cloud backups would copy the vault off the phone.
- On disk there is exactly one encrypted HMVAULT1 blob (`src/lib/vault/vault-context.tsx`); decrypted seeds, secret files, notes, passwords and the unlock password live in memory only and are dropped on lock. Why: a stolen phone image must never hold plaintext.
- Backups and the vault use the open HMVAULT1 format (`docs/seed-vault-format.md`, `src/lib/vault/format.ts`), and `src/lib/vault/standalone.ts` must keep opening every format we write. Why: seeds must stay recoverable without this app.
- Capacitor `hostname` (`vault.local`) is fixed after release. Why: localStorage is keyed by origin, so changing it orphans installed vaults.
- The Capacitor entry generator reuses the root SPA shell for seed-vault routes only; never prerender removed wallet routes. Why: nonexistent routes return 404 and block APK and web builds.
- Vault rules (lockout, auto-lock, merge, key derivation) live as pure functions in `src/lib/vault/seeds.ts` with tests beside them. Why: security rules stay testable without a UI.
- Offline signing (`src/lib/signer`) requires explicit PSBT network selection (TXC legacy coin-0 remains TXC only when selected), verifies every input fingerprint/path/script and SIGHASH_ALL, and permits EVM native/ERC-20 transfers only with chain-bound fees and matching sender; signed raw hex leaves by QR. Why: PSBT has no chain ID, and blind calls or unverified fees defeat offline review.
- EVM signing uses local viem account signing, strict versioned transfer intents and locally encoded ERC-20 calldata; unknown networks/tokens display raw units. Why: the vault cannot fetch trusted metadata and must never accept opaque contract calls.
- Secret entries are optional in the version-1 payload; full backups include seeds and secrets and legacy seed-only backups remain readable. Why: backups must remain recoverable across app upgrades.
- Offline transfer HTML is generated by `bun scripts/generate-vault-transfer.mjs` from `transfer-page.entry.ts` into `transfer-page.ts`; regenerate after its dependencies change. Why: downloaded pages must contain their QR decoder/encoder and encryption code without remote resources.
- Android document save/open uses the local VaultDocuments SAF plugin installed by the manifest patch script, without broad storage permissions. Why: owners can choose a USB drive without granting access to the entire device.
- Pending document imports retain only encrypted HMVAULT1 ciphertext in provider memory across a picker-triggered lock. Why: background locking must still discard every decrypted secret without losing the selected encrypted backup.
- Multi-part QR transfers use content-labelled HMQR2 framing, bounded input and conflict rejection; collectors still read HMQR. Why: separate transfers must not silently mix and old signed-payment codes must remain readable.
