# Vault library rules

- Service-specific pairing QR payloads filter the full `pairingPayload` output without independent derivation. Why: restricted disclosures must use the exact same account keys as wallet pairing.

- Offline transfer HTML is generated by `bun scripts/generate-vault-transfer.mjs` from `transfer-page.entry.ts` into `transfer-page.ts`; regenerate after its dependencies change. Why: downloaded pages must contain their QR decoder/encoder and encryption code without remote resources.
- Pending imports retain only encrypted HMVAULT1 ciphertext in provider memory until successful import or explicit discard; unlocking resumes Backup → Receive when ciphertext is pending. Why: background locking must still discard every decrypted secret without losing the selected encrypted backup or sending its owner to Seeds.
- Multi-part QR transfers use content-labelled HMQR2 framing, bounded input and conflict rejection; collectors still read HMQR. Why: separate transfers must not silently mix and old signed-payment codes must remain readable.
- Backup parsing recomputes seed fingerprints, normalizes words, cleans/caps names and drops duplicates (`parsePayload`). Why: crafted backups must not plant look-alike seeds.
- Secret entries are optional in the version-1 payload; full backups include seeds and secrets and legacy seed-only backups remain readable. Why: backups must remain recoverable across app upgrades.
